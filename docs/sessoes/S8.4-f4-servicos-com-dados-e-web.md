## 4. Decisões tomadas

- **Leitura fica na API, escrita de edição no editor**: `GET /produtos/:id` e `GET /geometrias/:id` na API;
  `PATCH`, `PUT`, `restaurar`, `original` no editor. O web lê de um e escreve no outro.
- **`PATCH /catalogos/:id` (metadados) fica na API de catálogo**: não é edição de peça.
- **Editor e API escrevem nas mesmas coleções** — acoplamento aceito da POC (ADR-004/014), registrado em
  `docs/arquitetura.md` §5.
- **Portas e URLs com o nome do contexto** (`CRIADOR_PORT`, `CATALOGO_URL`…) — `PORT`/`INGESTAO_*` saíram.

## 6. Surpresas — e um erro meu

- **Apaguei o storage local.** Na segunda tentativa da F4a, depois de um `git reset --hard`, rodei
  `git clean -fdq` na raiz para tirar restos de uma rodada anterior; o `storage/` já tinha sido movido para
  a raiz (pelo script) mas o `.gitignore` ainda dizia `www/storage/` — o diretório estava sem proteção e
  foi apagado: geometrias, miniaturas e os downloads do plugin da base local. Os documentos do Mongo
  ficaram órfãos. Como os catálogos da POC são descartáveis (decisão do usuário em 2026-09-03), apaguei
  os catálogos órfãos pela API e reimportei as quatro bibliotecas pelo criador (§3). O que não voltou: os
  arquivos IGES/RFA baixados do catálogo web (`catallog/…`) — o catálogo do plugin foi reimportado do
  `.aq` do estudo, sem a origem. Lição: **antes de `git clean`, conferir o `.gitignore` do estado atual**,
  e mover dados locais só depois de o ignore acompanhar; registrado em `docs/conhecimento/servicos-web.md` (F6).
- `git mv` de um diretório para um destino que já existe move *para dentro* dele: uma rodada anterior deixou
  `web/` com `node_modules` e o web foi parar em `web/web`. Limpar os destinos antes de rerodar.
- Duas substituições automáticas deixaram `}),` sobrando (`/cad` e `ProductEditor`); o `tsc --noEmit` do web pegou.
- O harness do editor testava o `GET /produtos/:id` no controller de edição — a leitura é da API; o harness
  passou a instanciar os dois.
