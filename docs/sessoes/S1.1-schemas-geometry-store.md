## 4. Decisões tomadas

**`_id` como string UUID v4** (`crypto.randomUUID()`, Node 24 nativo): evita ObjectId do Mongoose nos schemas, alinha com o padrão da bilds.com (UUIDs como PK). KTD confirmado no plano.

**`specs` como `Schema.Types.Mixed`**: os specs dos produtos são `Record<string, string>`, mas o schema de chaves é desconhecido em tempo de modelagem. `Mixed` evita enumeração prematura. KTD confirmado.

**`updatedAt` manual em `bim_imports`**: Mongoose `timestamps: true` adiciona `updatedAt` em toda modificação de documento; `bim_imports` precisa de `updatedAt` só em transições de estado (a regra de negócio é explícita). Campo `Prop({ type: Date })` sem default, atualizado pelo código de negócio.

**`IMPORT_STATUSES` como `const` array**: as strings de estado são usadas tanto no `enum` do Prop quanto no type derivado `ImportStatus`. Array `as const` permite derivar ambos de uma fonte única.

**`DiskGeometryStore` sem validação de path traversal (achado #1)**: o achado foi identificado como risco latente P2 (`manual`), mas a política de validação de chaves é uma decisão de design para S1.2 (quando as chaves serão derivadas de nomes de arquivo de upload externo). Aplicar antes de definir o escopo da validação arriscaria sub-corrigir. Ver seção 5.

## 5. O que NÃO foi feito, e por quê

**Achado #1 do ce-code-review — path traversal em `DiskGeometryStore`:** `path.join(this.baseDir, key)` não impede que uma chave com `../` escape de `baseDir`. Exemplo: `get('../../etc/passwd')` retorna um arquivo fora do storage.

Não foi corrigido por ser uma decisão de design, não um bug mecânico: a solução correta depende de onde as chaves são originadas. Em S1.1 as chaves são geradas internamente (hardcoded no smoke test). Em S1.2 as chaves serão derivadas de nomes de arquivo de upload — esse é o ponto onde a validação deve entrar.

**Ação para S1.2:** antes de derivar qualquer `geoKey` de dados externos (ex: `fileName` do upload), implementar validação no `DiskGeometryStore.put/get/delete` ou na camada de serviço que gera as chaves. Validação sugerida:

```typescript
private validateKey(key: string): void {
  const resolved = path.resolve(this.baseDir, key);
  if (!resolved.startsWith(this.baseDir + path.sep)) {
    throw new Error(`Key escapes storage root: ${key}`);
  }
}
```

## 6. Surpresas — onde a documentação estava errada

**`readdir` com `{recursive: true}` retorna diretórios junto com arquivos.** O plano não especificava esse detalhe. A primeira implementação de `deleteByPrefix` usava as strings retornadas pelo readdir, chamava `unlink` em cada uma, e quebrava com `EISDIR` quando o prefixo casava com um diretório (ex: `geo/import1`). A correção exigiu `{withFileTypes: true}` + `.isFile()`.

Não há documentação incorreta no plano a corrigir — o comportamento do Node não estava descrito e a descoberta veio do smoke test.
