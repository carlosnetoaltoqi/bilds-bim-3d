## 4. Decisões tomadas

**PocProduct/PocCatalog em vez de reutilizar tipos da bilds.com.** A bilds.com usa
`product.geo` (filename) + `geoBaseUrl`; a POC retorna `product.geoUrl` (caminho relativo
por produto) + sem baseUrl. Criar tipos próprios evitou props desnecessários e deixa
claro que é uma interface diferente.

**URLs absolutas no Server Component.** O page.tsx converte `geoUrl: "/geometrias/:id"`
→ `"http://localhost:4000/geometrias/:id"` no servidor, antes de passar ao cliente.
Alternativa seria fazer a conversão em cada componente cliente — mais frágil.

**Tailwind via `@tailwindcss/postcss` (v4).** O `tailwindcss.config.js` não existe neste
projeto. A instalação `pnpm add --filter web tailwindcss @tailwindcss/postcss` + postcss +
globals.css foi suficiente.

**`three` e `@types/three` instalados no pacote `web`.** `pnpm add --filter web three @types/three`.

**`catalogSlug` adicionado ao `findLatestByOwnerId`** via join com `bim_catalogs`. Sem isso
a empresa page não poderia construir o link para o catálogo sem um endpoint adicional.

## 5. O que NÃO foi feito, e por quê

**Thumbnails no LazyBimCard via BimViewer gerados no cliente (render dinâmico).** O
`LazyBimCard` ainda renderiza o WebGL no browser quando `thumbUrl` é null — mesmo fluxo
do engine da bilds.com. Como a POC já gera `thumbUrl` para todos os produtos Dancor
(S2.4), na prática o WebGL não é chamado nesta demo. A otimização de LCP fica para a
bilds.com production.

**Testes de tipos com `tsc --noEmit`.** A compilação Next.js já faz checagem de tipos
em dev. Não foi rodado separadamente.
