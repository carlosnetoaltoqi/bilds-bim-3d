## 4. Decisões tomadas

**`child_process.fork()` em vez de worker_threads para o parse-worker**
`node:sqlite` usa `DatabaseSync` que bloqueia o event loop. Worker Threads compartilham o
event loop do processo principal; `fork()` cria um processo OS separado. Custo: ~300 ms de
startup + IPC serialization de `WorkerResult` (tamanho tipicamente < 1 MB para Dancor).
Benefício: isolamento completo — falha no worker não derruba o servidor.

**multer via transitive dep (`@nestjs/platform-express`)**
multer v2.0.2 chega como transitive dep de `@nestjs/platform-express`. O NestJS resolve
multer de `node_modules/@nestjs/platform-express/node_modules/multer` no virtual store do
pnpm. `FileInterceptor` de `@nestjs/platform-express` (não de `@nestjs/common`) usa esse
mesmo path. Não foi adicionada dependência direta — aceito como risco de patch version.

**MAX_FILE_BYTES = 300 MB**
O `.aq` é SQLite raw com BLOBs de geometria — diferente dos ZIPs comprimidos da bilds.com.
O arquivo Dancor tem 153 MB. A Amanco ultrapassa 400 MB (razão por que o teto ficou em 300
e não 50 como na tentativa inicial). Ver comentário no código.

**Validação ZIP manual sem lib externa**
Reutilizou o padrão do `extractSQLiteFromZip()` em `aq-reader.ts` — parsing de Local File
Headers com Node built-ins. Evita dependência adicional no API package.

**Upload duplicado: regra de substituição total**
Quando há catálogo existente para `companyId + slug`, o import anterior é inteiramente
substituído: produtos são deletados, arquivos geo do import anterior são removidos com
`deleteByPrefix`. O `note` registra o evento no documento de importação. Escolhido sobre
merge parcial pela simplicidade e previsibilidade da semântica para o usuário.

## 5. O que NÃO foi feito, e por quê

**Guard de autenticação nos endpoints**
Intencional para POC. Finding A1 do review S1.2 continua aberto. Não expor em rede sem
`@UseGuards()`.

**Cleanup do diretório vazio após `deleteByPrefix`**
`DiskGeometryStore.deleteByPrefix` apaga arquivos mas não remove diretórios vazios. O
diretório do import anterior fica vazio no disco. Decisão: comportamento aceitável para POC;
diretórios vazios são inofensivos e o cleanup não vale a complexidade extra.

**Guardar o `.aq` original (questão 2 do plano §12)**
Não guardado. O arquivo temporário é removido após o parse. A questão continua aberta.

**Rota GET /thumbs funcional**
Retorna 404 por design — responsabilidade da S2.4.

**Teste HTTP automatizado para as rotas**
As verificações foram feitas manualmente via `curl`. Não foi escrito teste automatizado de
integração HTTP — a sessão priorizou a funcionalidade. O smoke test cobre o `GeometryStore`
mas não os endpoints.

## 6. Surpresas — onde a documentação estava errada

**413 Payload Too Large no primeiro upload**
O plano e o CLAUDE.md não documentavam o tamanho real do `.aq` Dancor (153 MB). O limite
inicial de 50 MB veio de analogia equivocada com os ZIPs da bilds.com (que são comprimidos).
Corrigido para 300 MB com comentário no código explicando a diferença. O CLAUDE.md da seção
S1.2 mencionava `bim_geometries` como coleção — na POC os documentos ficam em `bim_products`
(schema diferente do que a menção antiga sugeria).

**`readdir` recursivo retorna 0 arquivos no diretório do import anterior**
Investigado no debug final: o `deleteByPrefix` funcionou corretamente — os 13 arquivos foram
apagados. O `readdir` com `{ recursive: true, withFileTypes: true }` retorna só `.isFile()`,
e o diretório vazio não produz entradas de arquivo. O "AINDA EXISTE" do script de verificação
checava a existência do diretório, não dos arquivos. Não há bug no `deleteByPrefix`.
