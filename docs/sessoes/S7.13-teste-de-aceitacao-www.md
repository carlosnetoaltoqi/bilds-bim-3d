## 1. O que era para fazer

Executar os cenários que S7.11 §7 e S7.12 §7 deixaram pendentes por precisarem da API rodando:

1. dois uploads seguidos → o segundo em `recebido` com `na fila — 1 à frente` (I11);
2. matar a API no meio de um import e subir de novo → `falhou` com "a API foi reiniciada" (I11);
3. `PATCH /produtos/:id` com `{ "specs": { "a": { "b": 1 } } }` → 400 com "recebeu object" (I16);
4. `GET /health` com o Mongo inacessível → 503 (I12);
5. editar geometria em `PUT /geometrias/:id` → log `miniatura regerada após edição`, `thumbAtualizadaEm`
   no produto, imagem nova em `GET /thumbs/:id`; provocar uma falha e ver `thumbErro`; restaurar (I14).

Critério da fase: o que a execução acusar de errado vira correção de código **com teste** e registro
no conhecimento.

## 4. Decisões tomadas

- **Miniaturas dentro da vaga da fila.** `common/fila.ts` dizia que a fila existe para não ter "dois
  workers + dois Chromiums"; a execução mostrou dois Chromiums. Preferi cumprir o documento a
  reescrevê-lo: o segundo upload espera as miniaturas do primeiro (Amanco: 80 s para 856 peças). O
  status do primeiro já é `publicado` e o catálogo já responde — quem espera é só o próximo import.
  Se isso se mostrar lento demais, `IMPORTACOES_CONCORRENCIA=2` é a saída sem mexer em código.
- **Nome do arquivo: decodificar no código, não subir o multer.** O multer que roda é o 2.0.2 que o
  Nest 10 fixa em `dependencies` (o `multer@2.3` do `package.json` só fornece o `diskStorage`);
  `defParamCharset` chega ao busboy e não faz nada nessa versão (provado com um servidor mínimo:
  multer 2.3 isolado decodifica certo com a opção). Um `pnpm.overrides` resolveria, mas mexe na
  árvore de peers que o I12 acabou de arrumar. A guarda de ida e volta em `nomeOriginalUtf8` faz a
  função virar identidade se o multer do Nest um dia decodificar UTF-8.
- **Simular "Atlas bloqueado" com um proxy TCP local** em vez de mexer na whitelist ou instalar Mongo:
  `mongodb://…@127.0.0.1:27018/?directConnection=true&authSource=admin` na segunda API; o proxy
  Python abre TLS para um nó do cluster com `server_hostname` (sem SNI o Atlas responde
  `tlsv1 alert internal error`). Matar o proxy = Mongo fora. Receita em `diagnostico.md`.
- **Catálogos criados no teste ficam na base** (Komeco, Intelbras Dispositivos, Amanco) — são POC e o
  Amanco com 856 peças é uma fixture útil para o editor; a tabela de estado foi refeita.
- **I32 fica aberto** (500 após 30 s com o Mongo fora): é um erro acusado, não engolido; a forma da
  resposta (guard global 503 vs `bufferCommands: false`) é decisão de produto.
