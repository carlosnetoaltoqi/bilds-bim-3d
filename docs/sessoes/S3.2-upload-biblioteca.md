## 4. Decisões tomadas

**Upload direto para a API em dev mode.** O Next.js 15 em dev mode trunca o body em 10 MB
antes de chegar ao route handler (comportamento da dev tooling para inspeção de HMR). O `.aq`
da Dancor tem ~153 MB — o proxy via Next.js não funciona. Solução: o browser faz o upload
diretamente para `http://localhost:4000/importacoes` usando CORS (já configurado na API) e
Bearer token obtido via `GET /api/auth/token`. Esse endpoint expõe o JWT ao JavaScript do
cliente — aceitável na POC (usuário único, token de 7 dias). Em produção: usar proxy com
streaming ou upload direto para S3 via presigned URL.

O route handler `POST /api/importacoes/route.ts` foi mantido para o caso de produção (sem
o limite de 10 MB do dev), mas não é usado pelo browser agora.

**Empresa derivada do JWT, não de query param.** Removeu o `?empresa=<customUrl>` do
`POST /importacoes`. A empresa é encontrada por `{ ownerId: req.user.sub }` — mesma lógica
do `GET /empresas/minha`. Mais seguro: elimina a possibilidade de um usuário subir para a
empresa de outro passando um customUrl arbitrário.

**Recovery por `/importacoes/ultima`.** A página chama esse endpoint no `useEffect` inicial.
Se retornar um import em estado não-terminal, inicia polling imediatamente. Se retornar
`null`, mostra o formulário de upload. Se retornar um estado terminal, mostra o resultado
sem polling.

**`vazio` distinto de `falhou`.** Implementado conforme a seção 7.5 do plano: box amarelo
com explicação ("tubos e kits não têm forma fixa") em vez de box de erro vermelho.

## 5. O que NÃO foi feito, e por quê

**Link para o catálogo na tela de sucesso.** A S3.3 ainda não existe, então a URL pública do
catálogo (`/{empresa}/{slug}`) não funciona. O texto "Catálogo publicado!" aparece com o
produto count, mas sem link clicável. S3.3 fecha isso.

**Validação de formato `.aq` no frontend.** O input tem `accept=".aq"` mas não valida
MIME type — o usuário pode renomear qualquer arquivo como `.aq`. A API rejeita com erro
tipado quando o arquivo não é um SQLite válido (o parse-worker falhará e gravará `falhou`
com o erro).

**Progresso granular dentro de `gravando`.** A tela mostra apenas o estado
`gravando` sem indicar quantos produtos já foram gravados dos N totais. Para a Dancor
(13 produtos, ~3 s total) é imperceptível; para a Amanco (457 geometrias) pode ser
longo. Não implementado — a S3.2 não exige granularidade intra-estado.

## 6. Surpresas — onde a documentação estava errada

**Limite de 10 MB do Next.js em dev mode.** O CLAUDE.md e o plano não documentavam
isso. O limite trunca o body silenciosamente em dev: a API recebia os primeiros 10 MB e
tentava abrir como SQLite, falhando com erro de parse. A workaround (upload direto com
token) funciona e está documentada neste registro.

**Processo web antigo na porta 3000.** Ao testar, o web server da sessão S3.1 ainda estava
rodando com código antigo. Matar e reiniciar é obrigatório — a armadilha já estava documentada
no S3.1 para a API, mas não para o web.
