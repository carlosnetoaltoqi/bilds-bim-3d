## 5. O que NÃO foi feito, e por quê

**LCP com Lighthouse real.** A medição de LCP não foi feita com Lighthouse real em nenhuma sessão desta POC — WSL não tem browser headless com DevTools para Web Vitals. Registrado na seção "O que a POC não implementou" como item pendente para a reconstrução.

**Re-importação do catálogo Dancor ativo.** O import ativo (`bim_imports` prefix `563e5794`) não tem deduplicação de vértices — geo files são 4× maiores que o necessário. Não foi re-importado nesta sessão (seria mudar o estado do banco para fazer uma sessão de documentação). O problema está documentado como obrigatório na reconstrução.

**Phase 3 (specialized reviews)** do `ce-compound` foi omitida por não ser aplicável — o documento não é `performance_issue` nem `security_issue`. A única especialização aplicável seria code simplification, mas o documento não tem código de produto.

## 6. Surpresas — onde a documentação estava errada

**Nenhuma.** A documentação do plano e dos registros de sessão estava correta. O estado do repositório correspondeu ao que estava registrado.

A única observação é que o `validate-doc-claims.py` inicialmente marcou `563e5794` como SHA git suspeito — é um prefixo de ObjectId do MongoDB, não um SHA. Anotação adicionada no documento para clareza futura.
