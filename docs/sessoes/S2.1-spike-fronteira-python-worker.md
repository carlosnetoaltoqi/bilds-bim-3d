## 1. O que era para fazer

Worker Python isolado recebendo o `.aq` como stream HTTP e escrevendo geometrias via `DiskGeometryStore` + documentos no Atlas, sem tocar em `input/` nem em `output/`. Pico de memória medido e registrado.

**Pronto quando:** uma biblioteca entra pelo contrato do worker e sai como arquivos + documentos, sem o worker tocar em `input/` ou `output/`; pico de memória medido e registrado.

```
www/package.json                         ← novo script worker:test
docs/plans/2026-08-29-002-feat-s2-1-python-worker-spike-plan.md  ← plano do spike
```

O worker:
- Recebe o `.aq` como `application/octet-stream` em `POST /parse`
- Escreve o body num `NamedTemporaryFile`, chama `read_aq.extract_simbologias()` e `read_aq.extract()` para obter blobs de geometria e metadados
- Para cada peça com simbologia OQ3D: chama `oq3d.to_buffers(blob)` e grava o JSON no `DiskGeometryStore` Python com key `geo/{importId}/{productUuid}.json`
- Insere os documentos `bim_products` via `pymongo.insert_many` e faz upsert em `bim_catalogs`
- Mede `tracemalloc` (heap Python) e `resource.getrusage(RUSAGE_SELF).ru_maxrss` (RSS OS) antes e depois do parse
- Retorna `{ status, productCount, peakMemoryMb, peakTraceMb, elapsedMs }`

## 4. Decisões tomadas

**`extract_simbologias` + `extract` (duas chamadas separadas) em vez de `open_aq` manual.**
A alternativa era abrir o SQLite uma vez com `open_aq()` e correr as queries manualmente — menor I/O, mas mais código replicando lógica de `read_aq.py`. Para o spike, chamadas separadas são mais simples e o overhead de re-abrir o tempfile é negligível (arquivo < 1 MB em disco).

**virtualenv local em `www/workers/aq-parser/.venv/`.**
O sistema (Ubuntu/WSL com Python 3.12) está em "externally managed environment" (PEP 668). Tentativa de `pip install --user` falhou. A solução correta é virtualenv. O `.venv/` não está commitado (gitignore implícito de `__pycache__` e venv convencionais). A sessão seguinte que usar o worker precisa de `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`.

**PYTHON_BIN no test script prefere `.venv/bin/python3`.**
`test-worker.ts` resolve `workerDir/.venv/bin/python3` e cai para `python3` se não existir. Isso torna o teste reproduzível sem precisar ativar o venv manualmente.

**productId em `bim_products` usa UUID gerado no worker** (não `ID_PECA` do .aq).
`ID_PECA` é um inteiro de banco SQLite, não um UUID nem um slug. Usar UUID garante unicidade global e alinha com o schema da coleção (`_id` como UUID string). O campo `id` recebe `str(ID_PECA)` para referência ao objeto original.

**`peakMemoryMb` como delta RSS (`rss_after - rss_before`).**
`ru_maxrss` no Linux é o pico histórico do processo (em KB). O delta captura o acréscimo de RSS durante o parse. Como o Flask já está carregado antes do `rss_before`, o número representa o custo de parse. Comparação justa com S2.2 (que medirá o mesmo delta no Node).

## 5. O que NÃO foi feito, e por quê

**`bim_imports` state machine não atualizada.** Está no escopo de S2.3. O worker desta sessão não cria nem atualiza documentos `bim_imports` — só `bim_catalogs` e `bim_products`.

**Miniaturas.** Estão em S2.4. `thumbKey` fica `null` em todos os documentos.

**Fila real (SQS/BullMQ).** O contrato HTTP local é suficiente para provar a fronteira. A substituição por fila é uma mudança de transporte, não de lógica.

**Limpeza dos dados de teste.** Ficou fora de escopo. Para limpar:

## 6. Surpresas — onde a documentação estava errada

**`read_aq.extract_products()` não existe.** O plano (U1 Approach step 5) mencionava essa função. A API real é:
- `read_aq.extract_simbologias(aq_path)` → `(simbologias, por_peca)` para os blobs de geometria
- `read_aq.extract(aq_path)` → `{ grupos, pecas, curvas, propriedades }` para os metadados

A implementação usou essas funções corretas. O plano não foi corrigido retroativamente (está arquivado como spec do spike).

**Python 3.12 no WSL está em "externally managed environment" (PEP 668).** O plano assumia que `pip install --user` funcionaria. Falhou. Solução: virtualenv. O `CLAUDE.md` deveria registrar isso como armadilha — feito abaixo (seção 7).

**Nome do arquivo `.aq` da Dancor.** O plano referenciava `pecas_dancor_bombas.aq`, mas o arquivo real é `pecas_dancor_bombas_incendio_2026_04.1.aq`. O test script usa o nome correto.
