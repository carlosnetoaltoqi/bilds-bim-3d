# S8.3 — F3: serviços stateless `gerador-zip` e `conversores`

**Data:** 2026-09-06 · **Sessão do plano:** S8 / F3 (`docs/arquitetura.md` §6) · **Status:** concluída
**Commits:** `refactor(S8/F3)` + `docs(S8.3)` (SHAs no `git log`).

## 1. O que era para fazer

Os dois contextos sem dados como deployables próprios (ADR-012, ADR-013): `servicos/gerador-zip`
(:4200, `POST /zip`) e `servicos/conversores` (:4300, `POST /tesselar`, `POST /aq`,
`POST /plugin/inspecionar`), usando o bootstrap comum da base; as rotas correspondentes saem do
serviço de ingestão; o web ganha um cliente por serviço. Critério: os dois sobem **sem** `MONGODB_URI`.

## 2. O que foi feito

- **`@bim/base` ganhou o cliente tipado da biblioteca:** `biblioteca.ts` (`class Biblioteca extends BibliotecaCli`
  — `catalogoDeAq`, `catalogoDePlugin`, `inspecionarPlugin`, `tesselar`, `gerarAq`, `catalogoParaAq`,
  `gerarZipBilds`, `miniaturas`, com os contratos validados) — era o `PipelineService` da ingestão, que
  virou `@Injectable() class PipelineService extends Biblioteca {}` + re-export dos tipos. Sem isso os
  serviços stateless copiariam os métodos.
- **`geo-buffers.ts` e os validadores de `specs`/`curva` foram do `dominio` para a `base`**
  (`validadores.ts`): são o contrato `{pos,col,idx}` e regras de DTO, não dado de Mongo — e os
  conversores precisam deles sem importar `@bim/dominio` (regra 3).
- **`servicos/gerador-zip`** — `main.ts` (`iniciarServico`, `ZIP_PORT` 4200, `.env` da raiz),
  `app.module.ts` sem Mongoose, `zip.controller.ts` (`POST /zip`: `armazenamentoTemporario`,
  `Biblioteca.gerarZipBilds`, `enviarArquivo`), `health.controller.ts`, README.
- **`servicos/conversores`** — `POST /tesselar` (`TesselarDto.deflexao`), `POST /aq` (`ExportarAqDto`,
  vindo do `cad.dto.ts`), `POST /plugin/inspecionar`, health, README. Contratos `geometria` e
  `info-plugin` validados na saída da biblioteca.
- **Ingestão** — `cad/` removido; `exportacao` só com `GET /exportar/catalogo/:id` (agora via `enviarArquivo`);
  a rota HTTP `plugin-autocad/inspecionar` saiu (o import de plugin continua inspecionando a DLL
  localmente pela mesma função da biblioteca — mesma função, dois consumidores, zero cópia).
- **Web** — `src/servicos/zip.ts` (`ZIP_URL`, `ROTA_ZIP`) e `src/servicos/conversores.ts` (`tesselar`,
  `gerarAq`, `inspecionarPlugin`); `BotaoGerarZip`, `/cad` e `/importar/plugin` usam os clientes.
- **Raiz** — `pnpm dev` sobe os cinco; `dev:zip`, `dev:conversores`, `start:*`; `.env.example` com
  `ZIP_PORT`, `CONVERSORES_PORT`, `NEXT_PUBLIC_ZIP_URL`, `NEXT_PUBLIC_CONVERSORES_URL`; os serviços de
  `servicos/` leem o `.env` da raiz (o local foi copiado de `www/.env`, ambos gitignored).
- **Testes** — `test_www_config`: regra 5 (um cliente por serviço, URL só nos clientes) e regra 3
  (stateless: sem `@bim/dominio`, sem Mongoose, sem `STORAGE_PATH`); regra 2 estendida a `servicos/`;
  `test_www_deps` com seis importers; harness de validação aponta para o DTO dos conversores.
- **Bug achado no smoke:** o `Ajv` padrão não aceita `$schema` 2020-12 — toda validação de contrato
  falhava com 500 (`no schema with key or ref …/2020-12/schema`). `contratos.ts` usa `Ajv2020`.

## 3. O que foi verificado — e como

- `pnpm -r build` (seis projetos TS) e `tsc --noEmit` do web: verdes.
- Serviços novos subidos com `env -u MONGODB_URI -u MONGODB_DB pnpm dev`: `/health` de ambos responde
  `{status: ok, biblioteca: …}` — **stateless provado**.
- `POST /zip` com a fixture de bombas (`aq_grande`-irmã): 200, 13 produtos, 13 miniaturas, 9,4 s.
- `POST /tesselar` com `step_peca` (deflexão 0,5): `formato step`, `MM`, bbox 152×107×152, 5.504 △, 0,12 s.
- `POST /aq` com um triângulo: 200, `Pe_a_Teste.aq` 733 KB, `X-Aq-Resumo` exposto.
- `POST /plugin/inspecionar` com a fixture `dll_plugin`: host, plugin, versão e 6 categorias.
- `POST /importacoes` pela ingestão relançada (fixture `aq_pequena`, empresa `xpto`): `publicado`,
  262 produtos em 2 s — o contrato `catalogo` validado no caminho real.
- `/tmp` sem `zip-*`, `conv-*`, `plugin-*` após os smokes.
- Suíte: ver §8.

## 4. Decisões tomadas

- **O cliente tipado da biblioteca mora na base**, não em cada serviço: um método por CLI, um lugar.
  Cada serviço chama só o que é do seu contexto (o README de cada um diz o quê).
- **Inspecionar plugin**: rota HTTP só nos conversores; o criador inspeciona localmente ao importar.
- **`.env` da raiz** para os serviços novos (os antigos ainda leem `www/.env` até a F4).
