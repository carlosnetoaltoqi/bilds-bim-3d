## 4. Decisões tomadas

- **Reescrever em vez de aceitar o peso.** Decisão do usuário. O repo tem um só colaborador
  e um só clone conhecido (esta máquina); a integração git da Vercel está desligada desde
  2026-09-02, então nada consome `origin/main` automaticamente. Risco de force-push: mínimo.
- **Preservar `output/preview/{index.html,.gitignore,.gitkeep}` no histórico.** São os únicos
  arquivos rastreados ali e a landing é feita à mão (L8) — apagá-los do histórico perderia
  as versões da landing.
- **Remover também `eng-reversa/saida/`.** Três `.aq` gerados (8,2 MB) que a auditoria já
  apontava; hoje a pasta é gitignored e nada versionado a referencia.
- **Backup em bundle local, não em ref remota.** Uma ref de backup no GitHub manteria os
  398 MB lá, anulando o C6. O bundle em `/home/foltz/backups/` guarda a história antiga
  completa e não depende do GitHub.
- **Trocar os SHAs nos `.md` mecanicamente**, em vez de deixar nota "SHAs antigos". Um SHA
  antigo num documento não resolve mais em nenhum clone; melhor que `git show <sha>` funcione.

## 5. O que NÃO foi feito, e por quê

- **`--replace-refs` não foram criados** (`delete-no-add`): manteriam SHAs antigos resolvendo
  localmente, mas só nesta máquina, e poluiriam `refs/replace/`. Quem tiver um SHA antigo

- **O GitHub ainda reporta ~63 MB** (`gh repo view --json diskUsage`). Os objetos antigos
  ficam inalcançáveis no servidor até o `gc` deles, que não se controla. Nenhum clone novo
  os recebe — `git clone` já vem com 1,3 MB de pack.
- **Nenhum outro item da auditoria** foi tocado. O passo 2 (I1, I2, I3, I7, I8, I9) segue
  como próxima sessão.
- **`git gc` manual não foi necessário**: o filter-repo repacka e expira reflogs ao final.
